Диагностика записи в новый Kafka-топик, 27 ноября 2026 года

Та же машина, фикстура, две фазы и критерии, что и в load-test.txt. Код коммита
0d5ebae инструментирован через временный go test -overlay. В этой версии
franz-go v1.22.1 использовал стандартный интервал MetadataMinAge в 5 секунд.

Писатель записывал относительное время клиентских сообщений Kafka, постановки
голоса на отправку, ответа в callback и завершения ожидания по тайм-ауту.
Подробные сообщения Kafka сохранялись первые 8 секунд. События голосования
выбирались по порядковому номеру (первые восемь и затем каждая тысяча),
ошибке или задержке callback от секунды. Интервал 0,000 отсчитывается от
инициализации диагностического кода. seq обозначает номер локальной отправки.

Как воспроизвести на стенде из README с уже запущенными PostgreSQL и Kafka.
Команды из корня проекта распакуют коммит в отдельный временный каталог и
применят туда тот же диагностический код из load-diagnostic.patch.

project=$(pwd)
trial=$(mktemp -d)
git archive 0d5ebae | tar -x -C "$trial"
(
  cd "$trial" &&
  git apply --no-index --unidiff-zero "$project/reports/load-diagnostic.patch" &&
  TELEVOTE_DIAG_LOG="$trial/kafka-trace.txt" go test -tags=integration,load \
    -run '^TestSubmitVoteLoad$' -count=1 -v -timeout=3m ./tests/integration
)

Выдержка из трассы. Во время первых записей брокер сообщил клиенту, что ещё
не обслуживает запись в партиции 0, 1 и 2. В партиции 3 запись удалась.
Клиент запланировал повтор, для партиции 0 дождался обновления метаданных
через 5 с. К этому моменту ожидание отправки № 2 исчерпало её срок в 5 с.
В полном журнале 128 вызовов callback с context deadline exceeded. Сервер
вернул 128 ответов HTTP 500. После обновления метаданных партиция 0 приняла запись.
