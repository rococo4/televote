# Структура Go-сервиса

`cmd/televote` вызывает `app.Run`. Пакет `app` подключает PostgreSQL и Kafka, собирает сервисы через конструкторы, регистрирует HTTP-маршруты и запускает фоновые задачи. Публичные и административные методы описаны вручную в [OpenAPI](../api/openapi.yaml).

## Дерево приёма и подсчёта

```text
api/openapi.yaml
cmd/televote/main.go
internal/
  app/                        # сборка приложения, регистрация опросов и таймеры закрытия
  api/http/
    votes/                    # GET вопроса, cookie и POST голоса
    adminpolls/               # создание опроса и чтение отчёта с Bearer-токеном
    httperror/                # общий формат ошибок HTTP
  entity/                     # Poll, PollChoice, Ballot, VoteSubmitted, PartitionResult
  service/
    polls/                    # публикация опроса и отчёт
    voting/                   # допуск запроса и отправка голоса
    counting/                 # последний выбор зрителя и итог партиции
  adapter/kafka/              # топики, запись событий и чтение партиций в группе
  repository/
    pollsrepo/                # настройки, публикация опросов и чтение отчёта
    closurerepo/              # регистрация писателей, общий срок ожидания и решение о закрытии
    resultsrepo/              # UUID топика, частичные и общие итоги
  migrations/postgres/        # нумерованные SQL-миграции

tests/integration/            # проверки с настоящими Kafka и PostgreSQL
tests/e2e/                    # полный сценарий через HTTP
test-env/                     # Compose для зависимостей и демо-опрос
```

## Что происходит при POST

Зритель получил cookie через `GET /api/polls/{id}` и выбрал B. Если у B идентификатор 2, запрос выглядит так.

```http
POST /api/polls/c17c57c4-51b1-4d95-841f-1e44356f5608/votes
Content-Type: application/json
Cookie: televote_voter=7ae145ffec3648e0b8c637d601cc4682

{"choices":[2]}
```

1. Обработчик читает тело и вызывает `voting.Begin`. Время приёма фиксируется при допуске. Если этой реплике опрос ещё не знаком, `app` загружает его из PostgreSQL и обработчик повторяет `Begin`. Затем он разбирает cookie и JSON. [HTTP-обработчик](../internal/api/http/votes/handler.go) · [Загрузка опроса](../internal/app/publication.go)
2. `voting.Submit` вызывает `Poll.ValidateBallot`. В этом примере вариант 2 должен принадлежать опросу. Для множественного выбора метод также проверяет число вариантов и повторы. Сервис вычисляет ключ зрителя по ID опроса и cookie, собирает `VoteSubmitted` и передаёт его в `Publisher.Publish`. [Правила опроса](../internal/entity/poll.go) · [Подача голоса](../internal/service/voting/submit.go)
3. Kafka-адаптер выбирает партицию по ключу и ждёт подтверждения брокера. При успехе HTTP-обработчик отвечает `202 {"status":"accepted"}`. Если брокер недоступен или истёк срок ожидания, клиент получает `500`. `defer admission.Finish()` освобождает зарегистрированный запрос при любом исходе. При закрытии опроса сервис отдельно дожидается и незавершённых отправок в Kafka. [Публикация и ожидание](../internal/adapter/kafka/producer.go)

## Что происходит после закрытия

Таймер в `app` останавливает приём новых голосов и координирует реплики через `closurerepo`. Когда PostgreSQL зафиксирует общее решение, `service/counting` отправит `CLOSE` в каждую партицию без результата. Kafka распределит партиции между участниками группы этого опроса. [Порядок закрытия при сбое](../DESIGN.md#4-где-заканчивается-минута) · [Код подсчёта](../internal/service/counting/count.go)

Для каждого зрителя обработчик сохраняет последний допустимый выбор до первого `CLOSE`. На маркере `resultsrepo` записывает итог партиции в PostgreSQL. Если процесс упал раньше, следующий владелец прочитает партицию заново. Когда записаны все частичные итоги, SQL суммирует их в `poll_results`. [Запись итога партиции](../internal/repository/resultsrepo/queries/save_partition.sql) · [Публикация отчёта](../internal/repository/resultsrepo/queries/finalize.sql)

## Куда добавлять изменения

| Задача | Код и проверка |
|---|---|
| Новый административный метод | Описать контракт в `api/openapi.yaml`, добавить обработчик в `api/http/adminpolls` и операцию в `service/polls`. Проверить авторизацию и ответы в `handler_test.go`. |
| Новое правило выбора | Дополнить `entity.Poll.ValidateBallot` и таблицу примеров в `entity/poll_test.go`. Например, `[1,2]` допустим при двух разрешённых ответах, а `[1,1]` всегда даёт ошибку. |
| SQL-запрос к опросам | Добавить запрос в `repository/pollsrepo/queries/`, вызвать его из `pollsrepo` и проверить в `postgres_integration_test.go`. Для изменения таблиц добавить миграцию в `migrations/postgres/`. |
| Другой порядок допуска или тайм-аут | Изменить `service/voting` и проверить запросы до и после дедлайна с управляемыми часами в `submit_test.go`. |

Клиент внешней системы помещаем в `adapter/<имя>`, а SQL и преобразование строк в доменные типы — в `repository/<имя>repo`. Интерфейс объявляет пакет, которому нужна операция. Например, `service/voting` требует от `Publisher` один метод, а реализацию на Kafka подключает `app`.
